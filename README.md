# 점심결재 대작전 · device6

공개 게임 `chfhrdl01-netizen/hoonjung45`의 points5를 이어 수정한 `party30-20261115-device6` 소스입니다. 같은 방·게임 규칙·누적 점수를 사용하면서 PC와 모바일의 화면 구성과 조작 안내를 나눕니다. device6의 공개 배포와 PC·모바일 화면 적용을 확인했으며, 이전 points5의 실제 5판 진행 기록은 아래에 별도로 남겼습니다.

## 게임 진행

- 온라인은 2~8명이 메뉴와 캐릭터를 고르고 모두 준비하면 시작합니다. 전원이 다섯 판에 참여하며, 낮은 점수를 받은 사람도 다음 판을 계속합니다. 혼자 하는 랜덤 5판 연습도 컴퓨터와 같은 누적 점수 방식으로 진행합니다.
- 각 경기의 순위 점수를 합산합니다. 4명이면 4·3·2·1점, 2명이면 2·1점이며 동순위에는 같은 점수를 줍니다. 최종 동점은 공동 순위로 유지하고, 점심 대표 메뉴만 공동 1위 중 한 번 추첨합니다.
- 5판 종료 → 최종 점수표와 시상식 → 메뉴 승낙 → 희망자 커피 게임 → 엔딩으로 이어집니다. 참가자 기권으로 일찍 끝나면 실제 완료한 경기 수를 표시합니다.
- 메뉴 이의는 신청자당 한 번입니다. 이의 결투는 점심 메뉴만 바꾸며, 확정된 누적 점수·순위·공동 우승자 기록은 유지합니다. 이의를 받아 패한 이전 메뉴 제안자는 다시 도전할 수 없습니다.
- 경기 완료 뒤 대표 메뉴 제안자가 나가도 확정 점수표를 유지합니다. 남은 참가자가 메뉴 승낙을 계속할 수 있도록 대표 메뉴를 넘깁니다.

## PC와 모바일 화면

- 넓은 PC 화면은 큰 경기장과 오른쪽 정보 영역으로 나눕니다. 규칙·현재 누적 점수·참가자 현황을 함께 보고 키보드 안내와 화면 버튼을 사용할 수 있습니다. 작은 PC 창은 기존의 간결한 배치로 표시합니다.
- 모바일 세로는 짧은 진행 현황과 내 누적 점수를 위에, 이동·액션 버튼을 아래에 둡니다. 가로는 경기장과 엄지 조작부를 나란히 배치합니다. `규칙·점수` 버튼으로 전체 정보를 펼칠 수 있고, 경기 종료 후에는 전체 순위를 항상 표시합니다.
- 모바일 로비는 `새 방 만들기`와 `초대 코드로 입장` 탭으로 나눕니다. 초대 코드가 포함된 링크는 입장 탭을 자동 선택합니다. 탭 전환 시 닉네임·주문 참여 동의·방 코드를 보존하고, 연결 중에는 탭 전환을 막습니다. 닉네임 입력 후 Enter는 선택한 탭의 동작을 실행합니다.
- 모바일 안내는 키보드 키 이름 대신 화면 버튼을 기준으로 표시합니다. PC에서 정보·닫기 같은 일반 버튼에 포커스를 둔 채 Space를 누르면 해당 버튼을 조작하며 게임 공격을 발생시키지 않습니다. 경기장에 포커스가 있을 때의 기존 게임 키는 유지합니다.
- 화면 크기와 입력 방식 변경을 반영하고, 배치가 바뀔 때 눌린 게임 입력을 해제합니다. 정보 펼치기와 방 참여 탭의 표시 설정은 이 기기의 UI 상태이며, 다른 참가자의 게임 상태나 누적 점수를 변경하지 않습니다.

## 캐릭터와 조작

- 공식 대학 안내 및 재학생 전공 자료를 근거로 14개 대학·학부 그룹, 학과·전공 118개를 수록했습니다. 모집중지 재학생 전공 17개와 학사 계약학과를 포함하고, 2027 개편 이름은 검색 별칭으로 지원합니다. 출처와 범위는 `work/departments-official.json`에 있습니다.
- 근로생은 삭제했습니다. 시설물관리 역할은 별도로 유지했습니다.
- 학과 선택은 큰 버튼으로 여는 카드 창입니다. 대학별 버튼, 예전 이름 검색, 캐릭터 미리보기, 24개씩 더 보기를 제공합니다.
- 기존 캐릭터 얼굴·몸·색을 보존하며 학과별 옷·안경·가운·헤드셋 등 16종의 의상을 더했습니다. 학과 순서가 바뀌어도 모습이 유지되며 SVG를 재사용합니다.
- 모바일의 이동·액션 버튼은 화면 방향에 맞게 배치합니다. 게임 조작 버튼의 텍스트 선택과 길게 누르기 메뉴를 막고, 회전 시 눌린 입력을 해제합니다.
- 1대1은 본인 키패드 하나만 표시합니다. 관전자는 조작하지 못하며, 로컬 키보드 두 세트는 유지합니다. 짧은 가로 화면에서는 경기장과 조작부를 나란히 배치합니다.
- 엔딩의 건너뛰기·ESC·결과 보기 우회를 제거했습니다. 커피 배달 장면은 13초이며 참가자별 확정 주문을 오른쪽(모바일 아래)에 표시합니다. 전체 엔딩은 인원에 따라 40~43.5초, 종료 시 모두 로비로 돌아갑니다.
- 경기 시간이 틱 지연으로 유실되던 부분을 고치고, 호스트의 실제 마감시각과 참가자 시계 차이를 반영합니다. 늦은 입력은 과거 판정창에 적용하지 않습니다. 긴 중단은 최대 66틱으로 복구하므로 중단 중 모든 물리 충돌을 재생하는 방식은 아닙니다.
- 다리 완성 점수 우선순위와 횡단보도 도약 방향 오류를 수정했습니다. 본선 점수전 격투·식판에서는 탈락 후 복귀하며 기존 서바이벌 규칙은 유지합니다.

## 소스 구조와 빌드

수정할 기능별 원본 위치는 [게임 소스 구조](work/source/README.md)에 정리했습니다. `work/base.html`은 화면 HTML 템플릿이며, `work/source/manifest.json`이 소스 결합 순서와 배포 파일 이름을 관리합니다. 게임 판정·점수 진행·메뉴 승낙 등은 `work/`의 기능별 모듈에 있습니다.

저장소 루트에서 실행합니다.

```sh
node work/build.mjs
```

다음 세 파일을 루트와 `dist/`에 동일하게 생성합니다.

| 배포 파일 | 내용 |
| --- | --- |
| `index.html` | 화면 HTML |
| `assets/styles-device6.css` | PC·모바일 화면과 기능별 CSS를 우선순위대로 결합한 스타일 |
| `assets/app-device6.js` | 실행 순서를 보존한 게임 코드와 기기별 UI |

배포할 때는 CSS·JS를 먼저 올리고 `index.html`을 마지막에 반영합니다. 배포용 파일을 직접 수정하면 다음 빌드에서 덮어씁니다. 원래 방 통신·메인 앱·화면 장식의 세 실행 범위를 유지하므로 소스 조각을 각각 ES 모듈로 불러오지 않습니다.

QA 화면은 `node work/build-qa.mjs`로 별도 생성하며, 공개 배포에는 QA 코드를 포함하지 않습니다.

점수전 검사는 2·3·8명 전원 참여, 공동 순위와 대표 메뉴, 기권 처리, 메뉴 이의전 이후 점수표 보존을 확인합니다. 소스 구조 검사는 실행·CSS 순서, 문법, 배포 경로, 루트와 `dist` 파일 일치 및 QA 코드 제외 여부를 확인합니다.

device6의 UI 단위 검사는 화면·입력 방식 분류, 초대 링크와 참여 탭, 입력·동의 보존, 연결 중 전환 제한, Enter와 키보드 포커스, 정보 펼치기·최종 순위 표시, UI 동작의 게임 상태 보존, 배치 변경 시 입력 해제를 확인합니다. 실제 게임의 세 키 입력 경로에서도 일반 UI 버튼의 Space 동작이 게임 입력으로 가로채이지 않는지 검사합니다.

device6 브라우저에서 아래 구성마다 30종의 경기장 화면을 확인했습니다. 총 180개 레이아웃 검사에서 경기장·설명·조작부의 겹침과 검사 대상 내용의 넘침이 없었습니다.

| 뷰포트 | 화면 구성 | 확인 게임 수 |
| --- | --- | ---: |
| 1280×820 | PC · 오른쪽 규칙·점수 영역 | 30 |
| 390×844 | 모바일 세로 · 정보 접힘 | 30 |
| 844×390 | 모바일 가로 · 정보 접힘 | 30 |
| 390×844 | 모바일 세로 · 정보 펼침 | 30 |
| 844×390 | 모바일 가로 · 정보 펼침 | 30 |
| 360×640 | 작은 모바일 세로 · 정보 펼침 | 30 |

모바일 로비에서 참여 탭을 바꿔도 닉네임·방 코드·동의 상태가 유지되고 선택한 입력 영역만 표시되는 것을 확인했습니다. 정보 버튼에 포커스를 두고 Space로 펼침·접힘을 전환할 때 `aria-expanded`도 맞게 바뀌었습니다. 모바일 최종 점수표는 8명 전원을 메뉴 티켓보다 먼저 표시했으며, 문서와 뷰포트의 가로 너비가 모두 375px로 수평 넘침이 없었습니다.

공개 device6에서는 같은 동전 모으기 경기를 진행하며 1280×820과 390×844 사이로 화면 크기를 바꿨습니다. PC에서는 경기장 오른쪽에 전체 참가자 현황이 표시됐고, 모바일에서는 규칙·점수 영역이 접힌 채 하단 터치 조작부를 표시했습니다. 모바일의 키보드 보조 표시는 숨겨졌으며 화면을 바꾸는 동안 같은 경기가 계속 진행됐습니다.

위 결과는 브라우저 뷰포트와 확인한 경기 시점의 화면 검사입니다. 실제 휴대폰·태블릿 실측이나 모든 경기 시점의 검증으로 기록하지 않습니다. UI 단위 검사에서는 별도로 입력 방식(coarse/fine) 분기와 실시간 쿨타임·회수·결과 대기 안내 보존을 확인합니다.

이전 공개 points5에서는 다음 실제 진행을 확인했습니다. 이 기록을 device6의 공개 검증으로 간주하지 않습니다.

- 혼자 연습: 컴퓨터를 포함한 4명 전원이 5판을 마쳤습니다. 첫 세 판의 최하위 참가자도 탈락하지 않았으며, 최종 점수 17·13·13·8점에서 13점 두 명을 공동 2위로 표시했습니다.
- 온라인 두 탭: 같은 방에서 두 참가자가 5판을 끝까지 진행했습니다. 양쪽 최종 점수표가 돈가스 제안자 10점·1위, 국밥 제안자 9점·2위로 일치했습니다. 점수전 뒤 시상식에서 메뉴 승낙 화면으로 이어지는 것도 양쪽에서 확인했습니다.

기존 campus4에서는 30종 480개 시드 경기의 종료·순위·판정·상태 크기와 학과 선택·의상, 8명 주문 엔딩, 세로·가로 조작 화면을 점검했습니다. 화면 점검 기준은 390×844·844×390 뷰포트이며 모든 실제 기기나 모든 경기 시점을 검증한 것은 아닙니다. points5의 실제 공개 멀티 완주 확인 범위는 위 두 탭·2인전입니다.
